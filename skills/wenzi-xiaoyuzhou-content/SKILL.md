# 逐字稿自媒体内容生成器

把一份已经完成的逐字稿转化为“属于创作者本人”的内容，而不是压缩成通用摘要。它负责理解创作者想长期讲什么、想展示什么能力、想表达什么观点，再把来源素材匹配到合适的内容板块和平台。

## 输入路由

- 任何新用户先执行阶段 0。账号定位没有得到本人确认前，不分析逐字稿、不选题、不创作。
- 已有本人确认的定位档案：读取档案，直接进入对应阶段，不重复访谈。
- 用户要求“继续选题”“从选题池找内容”或类似操作：先读取该用户已经保存的选题池，优先处理其中 `待选择` 或 `已选择` 的条目，不重新分析全部逐字稿。
- 收到逐字稿、笔记或观点摘录：定位确认后进入素材匹配。
- 只收到播客链接：说明本 Skill 不负责转录，改用 `wenzi-xiaoyuzhou-transcribe` 生成逐字稿，并在逐字稿完成后结束本次基础工具任务；不要自动继续创作。
- 用户只要摘要或知识笔记：不要强行生成社媒文案。
- 用户要求发布：本 Skill 只产出草稿；发布必须另行获得明确授权。

## 分阶段工作流

默认不要在一次运行里把定位、素材匹配、选题和多平台创作全部做完。按四个阶段推进，并保留用户选择权。

默认使用“快速创作模式”，不要求建立或维护选题池。只有用户明确希望长期积累、跨会话继续或管理多个候选选题时，才启用“长期积累模式”并保存个人选题池。

### 阶段 0：用户定义账号定位

1. 查找当前对话、用户明确提供的档案，以及用户私有档案目录 `~/.codex/user-profiles/wenzi-xiaoyuzhou-content/`。
2. 只有用户本人明确确认过的档案才算可用。不要根据播客链接、平台名称、用户昵称或其他人的档案推断定位。
3. 没有可用档案时，读取 [账号定位初始化](references/account-profile.md)，请用户定义内容板块、能力信号和观点资产。此时停止，不继续处理逐字稿。
4. 根据用户回答整理一页定位摘要，明确哪些是本人事实、哪些是表达偏好、哪些仍待补充，再请用户确认。
5. 用户确认后才可保存为私有档案并进入阶段 1。保存是本地写操作，需要用户明确要求或同意；未要求保存时只在当前对话中使用。

### 阶段 1：逐字稿素材映射

1. 检查输入是否为可读的逐字稿，并保留来源、说话者和时间戳。逐字稿缺失或明显不完整时停止，交还基础工具处理。
2. 读取 [内容映射框架](references/content-framework.md)，从素材中寻找与用户内容板块有关的片段。
3. 对每个片段判断它可以展示哪种能力、承载哪条观点，以及适合哪种内容形式。此阶段不写成稿。

### 阶段 2：选题与内容方向确认

1. 读取阶段 0 已确认的账号定位。已有信息不重复询问，不借用其他用户档案。
2. 从逐字稿提取 3–5 个候选选题，每个候选只提供：一句话观点、时间位置、来源依据、内容板块、能力信号、观点资产、内容形式、适合平台和匹配理由。
3. 内容板块优先使用用户本人定义的名称。只有用户还没有自己的分类时，才参考 [通用选题池](references/topic-pools.md)。
4. 给出一个明确推荐，但不写正文。等待用户确认选题、内容板块、能力/观点重点和平台。
5. 用户希望长期使用时，读取 [个人选题池模板](references/topic-pool-template.md)，预览将要保存的候选选题并征得同意后，写入该用户的私有选题池。不要把真实选题写入公开 Skill 目录。

### 阶段 3：内容创作

只有用户确认选题、内容板块、能力/观点重点和平台后才开始。先形成一份内容母稿，再按目标平台改写；平台规则见 [平台适配](references/platforms.md)。默认只写用户选定的平台，每个平台只交付一个最佳版本。没有被选择的候选选题留在素材池，不继续加工。

首稿不是最终稿。交付首稿后进入“本人表达回合”：

1. 用户可以直接修改，也可以用口语重新讲一遍自己的意思；
2. Agent 只整理重复、语序、节奏和平台长度，保留用户新加入的用词、判断与语气；
3. 不因润色重新拔高观点，也不把用户的自然表达改回通用文案；
4. 用户确认后才形成发布稿。发布仍需另行明确授权。

这一步的目标不是让用户接受 Agent 的成稿，而是用首稿帮助用户说出自己的版本，再完成轻量整理。

如果用户启用了个人选题池，在开始创作、形成发布稿或用户告知已经发布时，分别把状态更新为 `创作中`、`待发布` 或 `已发布`。只有用户提供或明确要求记录时才填写发布链接、截图和发布日期；不要假设内容已经发布。

## 阶段成果

每个阶段都必须形成用户可识别的成果，而不是只报告过程：

- 阶段 0：一份由本人确认的账号定位档案；
- 阶段 1：有来源和时间位置的素材映射；
- 阶段 2：3–5 个候选选题，以及用户确认的一张创作卡；
- 阶段 3：AI 首稿和本人表达后的发布稿；启用个人选题池时，再更新对应的选题状态。

快速创作模式以“形成本人确认的发布稿”为结束；长期积累模式还需要更新个人选题池状态。两种模式都不以 Agent 写出第一版文案为结束。

## 档案隔离

- 公开 Skill 只包含定位字段、空白模板和流程，不包含作者或任何用户的个人档案。
- 私有档案存放在 Skill 目录之外：`~/.codex/user-profiles/wenzi-xiaoyuzhou-content/`。
- 不向其他用户展示、复用或概括某个私有档案。
- 分享、打包或上传本 Skill 时，不复制私有档案目录。

## 阶段 2 默认输出

```markdown
## 候选 1：选题名称

- 核心观点：
- 时间位置：
- 内容板块：
- 能力信号：
- 观点资产：
- 内容形式：
- 适合平台：
- 匹配理由：
- 风险或待核验：
```

候选列表之后只给一项推荐，并请用户选择；不要附带任何平台成稿。

## 个性化原则

- 个性化来自用户已确认的经历、立场、案例、语言习惯和受众，不是简单替换人称。
- 不虚构用户听过、用过、买过、采访过或亲历过某件事。
- 不把主播或嘉宾的经历写成用户的第一人称经历。
- 用户观点缺失时，可保留清晰的“本人补充位”，不要代替用户制造立场。
- 同一观点跨平台改写时保持事实与核心判断一致，只改变开头、节奏、结构、篇幅和互动方式。
- 引用、数字、专有名词或转录不确定处标记 `需核验`；能从原稿确认的内容由 Agent 直接核验。
- 不大段复制受版权保护的播客逐字稿。仅保留支撑观点所需的短摘录，并明确来源。

## 内容选择

优先选择同时满足以下条件的片段：

- 与账号内容支柱相关；
- 能回应目标受众的具体问题；
- 用户可以加入自己的判断、经验或方法；
- 脱离整期节目后仍能独立成立；
- 有明确出处，且事实风险可控。

如果素材与账号定位关联很弱，直接指出，并提供一个更自然的连接角度；不要硬蹭热点。

## 默认交付格式

```markdown
# 选题

来源：节目 / 嘉宾 / 时间位置
适合平台：
匹配的内容支柱：
能力信号：
观点资产：
面向受众：

## 核心观点

来源观点：
用户可加入的判断：
对受众的价值：

## 发布草稿

（按平台成稿）

## 发布前确认

- 需核验：
- 本人经历补充位：
- 建议配图或互动方式：
```

用户只要求成稿时，省略内部分析字段，只保留必要来源和待确认项。

## 质量检查

- 读者能看出为什么是这个账号在讲，而不是任何人都能讲。
- 内容保留播客原观点，但没有冒充来源作者或用户经历。
- 平台差异体现在结构和阅读场景，不只是字数变化。
- 开头提供真实的信息或冲突，不制造虚假悬念。
- 结尾符合账号目标，不默认使用套路式提问、关注引导或营销话术。
