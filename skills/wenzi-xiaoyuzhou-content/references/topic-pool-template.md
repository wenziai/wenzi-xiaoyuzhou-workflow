# 个人选题池模板

个人选题池用于保存从逐字稿中提取、但不一定立刻创作的候选内容。它是可选的长期管理功能，也是用户私有成果，不属于公开 Skill。只想完成一次内容创作的用户可以跳过。

## 保存位置

用户明确同意长期保存时，建议使用：

```text
~/.codex/user-data/wenzi-xiaoyuzhou-content/<profile-name>/topic-pool.md
```

目录不存在时可以在获得保存同意后创建。不要把真实选题保存在公开 Skill、示例文件或其他用户的档案中。

如果用户不希望保存文件，只在当前对话中展示候选列表，并明确说明它不会跨会话保留。

## 状态

只使用以下状态：

- `待选择`：已经进入选题池，尚未决定是否创作；
- `已选择`：用户已经选定，但还没有开始写；
- `创作中`：正在经历 AI 首稿、本人口语重述或修改；
- `待发布`：发布稿已经由本人确认；
- `已发布`：用户明确告知已经发布；
- `暂不采用`：本轮不继续，但保留来源和判断。

状态变化必须来自流程中的真实进展，不根据沉默或推测更新。

## 文件格式

```markdown
# <账号名称>的个人选题池

最后更新：YYYY-MM-DD

## 待选择

### TP-YYYYMMDD-01｜选题名称

- 状态：待选择
- 一句话观点：
- 来源节目：
- 来源链接：
- 说话者：
- 时间位置：
- 原文依据：
- 内容板块：
- 能力信号：
- 观点资产：
- 内容形式：
- 适合平台：
- 匹配理由：
- 风险或待核验：
- 本人可补充：
- 创建日期：
- 草稿位置：
- 发布日期：
- 发布链接：
- 发布后复盘：
```

按状态设置二级标题。状态改变时移动整张选题卡，不复制出多个版本。选题编号保持不变，用于以后继续指定某个选题。

## 写入规则

1. 首次保存前，展示准备写入的选题卡并获得用户同意；
2. 后续对已经授权维护的同一选题池，可按真实进度更新状态；
3. 不大段保存受版权保护的逐字稿，只保留支撑选题所需的短摘录和时间位置；
4. 用户说“从选题池继续”时，优先展示 `待选择` 和 `已选择`，默认不展开 `已发布`；
5. 用户告知已经发布时，可以更新为 `已发布`；发布日期、链接、截图或数据只有在用户提供或明确要求记录时填写；
6. 不删除 `暂不采用` 或 `已发布` 的条目，除非用户明确要求。

## 匿名示范

下面只演示一张选题卡应当长什么样，不对应任何真实用户或具体节目：

```markdown
### TP-20261005-01｜工具越省时间，判断越重要

- 状态：待选择
- 一句话观点：自动化降低了执行成本，也让选择做什么变得更重要。
- 来源节目：某期关于工作方式的访谈
- 来源链接：
- 说话者：嘉宾 A
- 时间位置：00:18:20–00:19:05
- 原文依据：嘉宾谈到工具缩短执行时间，但不会代替目标判断。
- 内容板块：AI 与工作流
- 能力信号：判断能力
- 观点资产：效率工具应该服务于清晰目标
- 内容形式：观点判断
- 适合平台：X、微博
- 匹配理由：能连接账号长期关注的 AI 实践与工作选择。
- 风险或待核验：确认原话语境，避免把条件性结论写成绝对判断。
- 本人可补充：自己如何决定哪些工作值得自动化。
- 创建日期：2026-10-05
- 草稿位置：
- 发布日期：
- 发布链接：
- 发布后复盘：
```
